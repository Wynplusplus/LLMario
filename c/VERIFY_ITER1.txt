 * Generated by gen_c.py from the matching disassembly analysis.
 * Code addresses are translated to C functions dispatched via optab;
 * data addresses have no entry and halt execution when reached.
 * The 32 KiB PRG image is retained so reads of data (and of code bytes
 * used as data) return the original values. Compiled freestanding for
 * x86-64 and aarch64; see build_c.sh. */
#include "cpu.h"


static void setnz(Cpu *c, u8 v) {
    if (v == 0) c->p |= F_Z; else c->p &= (u8)~F_Z;
    if (v & 0x80) c->p |= F_N; else c->p &= (u8)~F_N;
}
static void push(Cpu *c, u8 v) { c->mem[0x100 + c->s] = v; c->s = (u8)(c->s - 1); }
static u8 pop(Cpu *c) { c->s = (u8)(c->s + 1); return c->mem[0x100 + c->s]; }
static void push16(Cpu *c, u16 v) { push(c, (u8)(v >> 8)); push(c, (u8)v); }
static u16 pop16(Cpu *c) { u8 lo = pop(c); u8 hi = pop(c); return (u16)(lo | (hi << 8)); }
static void do_adc(Cpu *c, u8 m) {
    u16 r = (u16)c->a + m + ((c->p & F_C) ? 1 : 0);
    u8 res = (u8)r;
    if (r > 0xFF) c->p |= F_C; else c->p &= (u8)~F_C;
    if ((~(c->a ^ m) & (c->a ^ res)) & 0x80) c->p |= F_V; else c->p &= (u8)~F_V;
    c->a = res; setnz(c, res);
}
static void do_sbc(Cpu *c, u8 m) {
    u16 r = (u16)((u16)c->a - m - ((c->p & F_C) ? 0 : 1));
    u8 res = (u8)r;
    if (r < 0x100) c->p |= F_C; else c->p &= (u8)~F_C;
    if (((c->a ^ m) & (c->a ^ res)) & 0x80) c->p |= F_V; else c->p &= (u8)~F_V;
    c->a = res; setnz(c, res);
}
static void do_cmp(Cpu *c, u8 r, u8 m) {
    u16 t = (u16)r - m;

}

## Counterexamples (concrete failures)

Five real instruction entry points are **absent** from the generated C (`optab == NULL`, no `I_` function), confirmed by the **independent cc65 `da65` disassembler**:

| Address | ROM bytes | ROM instruction | Reached by (static) |
|---|---|---|---|
| `$8223` | `A0 04 A9` | `LDY #$04` | `JSR $8223` at `$814A` |
| `$C902` | `4C 7A D6` | `JMP $D67A` | `BNE $C902` at `$C8FD`, and return of `JSR $C905` |
| `$C905` | `B5 16 20` | `LDA $16,X` | `JSR $C905` at `$C8FF` |
| `$BFB7` | `A9 01 48` | `LDA #$01` | `JSR $BFB7` at `$D498`, `$D5F5` |
| `$DC21` | `B5 CF A4` | `LDA $CF,X` | `JSR $DC21` at `$D4BA`, `$D5CD`, `$D603`, `$D62D`, `$D639` |

**Demonstrated divergence** (`/tmp/opencode/demo2.c`):
```
$8223: optab=NULL  ROM bytes=A0 04 A9
$C902: optab=NULL  ROM bytes=4C 7A D6
$C905: optab=NULL  ROM bytes=B5 16 20
$BFB7: optab=NULL  ROM bytes=A9 01 48
$DC21: optab=NULL  ROM bytes=B5 CF A4

== NMI-path counterexample: $814A is 'JSR $8223' ==
C   after step1: pc=8223
C   after step2: rc=0 pc=8223   <-- HALT (no translation at $8223)
ref after step1: pc=8223
ref after step2: pc=8225   <-- ROM: A0 04 = LDY #$04
```

`$814A` is on the **NMI handler path** (da65: `L813D ... lsr a / bcs L8150 / jsr L8223 / jsr L81C6`), reached from the NMI vector `$8082`; the loop exits into `$811B` with `lda $0722 / beq L815C`, so when `$0722≠0` and `$0776` bit0=0 the call executes. This is ordinary live game code, not a runtime-pointer/data region — so the stated "code reached only via runtime pointers stays as data" limitation does **not** cover it.

### Root cause
These are **overlapping-code entry points** using the classic `BIT abs` skip idiom: the byte `2C` at `$8222`/`$BFB6`/`$DC20` is a 3-byte `BIT`, and its low operand byte (`$8223`/`$BFB7`/`$DC21`) is an alternate entry executed via a static `JSR`. `smb.asm` mis-decodes the alternate entries (it emits `.byte`/mid-instruction at `$C902`, etc.), and `gen_c.py` translates *only the instruction lines present in `smb.asm`* (`for line in open(ASM) ... instr[a]=...`). It never treats branch/JSR/JMP targets as new code starts, so the alternate entries get no function. `da65_linear.asm` independently shows the correct streams.

### The differential test cannot catch this
- Phase 1 enumerates `optab[addr]` — absent addresses are never tested.
- Phase 2 has `if (!optab[c1.pc]) break;` (difftest.c:102), i.e. a translation gap is silently treated as a normal end-of-trace, not as a mismatch.
- The test never starts traces from the reset/NMI/IRQ vectors.

### Minor secondary observation
The same traversal also **over-decodes** some data: e.g. `$A4B3` `LDA $C514,Y`, `$A513` `STA ($3E,X)`, and `$A535 JSR $52FD` / `$A53A JSR $406E` sit inside an unmistakable `.byte` level-data table (`$A405–$A534`) and call into RAM. Harmless unless reached, but it shows the code/data map is noisy in both directions.

---

## Trustworthiness summary
- The **semantic verification is non-circular and sound** for the instructions that exist: decode table == canonical, every emitted function is byte/operand-correct, `ref6502.c` matches an independently written spec model on 1.63M exhaustive/edge cases, and the generated C matches that independent model on 563,730 steps.
- The **verification is incomplete**: it validates `smb.asm`'s code map rather than the PRG's actual reachable instruction set, and its trace loop treats missing translations as clean termination.

## Instructions to fix

**Fix `gen_c.py`** (the code map is the real defect, not the semantics):
1. After parsing `smb.asm`, collect every static control-flow target: rel branch `val`, `JMP abs` operand, and `JSR` operand (and the fallthrough `npc` after a `JSR`, which is a return site). 
2. Iterate to a fixpoint: for any target `t` in `0x8000..0xFFFF` not already in `instr` and not overlapping a byte it cannot re-decode, call the existing `fields(t)` to decode it from `prg.bin` and add `instr[t]`; recurse over the new instruction's targets/fallthrough. Overlapping instruction streams are fine here because the emitter already keys one function per address.
3. Handle opcodes not in `OPS` (e.g. `$77` reached after the `$C905` routine) by not emitting a function/stopping that chain, rather than raising.
4. This adds `I_8223`, `I_C902`, `I_C905`, `I_BFB7`, `I_DC21`, … and the corresponding `optab` entries.

**Fix `difftest.c`** so gaps can't hide:
- In Phase 2, replace `if (!optab[c1.pc]) break;` with a step against `ref_step` and **report a mismatch** if the reference has a valid instruction at `c1.pc` (i.e. a gap in the translation).
- Add Phase 0 traces that start at the reset/NMI/IRQ vectors, and Phase 1b that also seeds states at every static branch/JSR/JMP target.

**No change required to `ref6502.c`** — its flag arithmetic, carry/overflow, zeropage wrapping, `JMP (ind)` page bug, and stack/B-U handling all verified correct against an independent spec implementation.
